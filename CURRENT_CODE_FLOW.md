# Current Code Flow

This document maps the current CarbonPATH source tree and the main execution
paths. It describes the live implementation, not the historical upstream
snapshot in `asu-vda-lab-carbonpath-8a5edab282632443.txt`.

```text

main.py or network.pyk

    |       |
    |       +--> legacy GEMM or ordered GEMM sequence
    |
    +--> calibration
    |       |

    |       +--> calibration statistics
    |
```

## Workload Flow

### Legacy and ordered GEMMs

`cfg/examples/workload.json` is loaded by `main.py` into `WORKLOAD_CONFIGS`.
`main.parse_workload_entry()` normalizes either:

- A legacy `[M, K, N]` triple into a one-GEMM sequence.
- A named multi-GEMM object into an ordered sequence.

It validates positive dimensions, unique names, and chained GEMM compatibility.
Workload 7 is the two-GEMM projection/classifier sequence. Workload 8 is the
four-GEMM repeated-block sequence.

### Network JSON

`system/utils/NetworkWorkload.py` handles network descriptions from
`cfg/experiments/dnn_workloads/`. `load_network()` validates the schema and
`LinearNetwork.to_workload_sequence()` converts linear layers into the same
ordered workload representation used by the simulator.

## Architecture Flow

`main.gen_initial_arch()` creates a candidate through `SystemGenerator`.

| File | Key responsibility |
|---|---|
| `chiplet/n_disagg.py` | Generates chiplets, packages, memory connections, protocols, and workload mappings. |
| `chiplet/n_utils.py` | Architecture mutation, area/power/SRAM calculations, bandwidth, carbon helpers, move acceptance, and output flattening. |
| `system/utils/ChipletSystem.py` | Converts architecture data into chiplet cores and the interconnect graph; provides route lookup and path costs. |
| `system/utils/SystolicArray.py` | Represents individual compute arrays and their tile/workload state. |
| `system/utils/GEMMWorkload.py` | Represents one GEMM and its tile decomposition. |
| `config.py` | Runtime flags such as `fast_test`, latency enablement, and SRAM selection mode. |

## Calibration Flow

`main.get_calib_cost_avg()` samples random architectures and records metric
statistics used for objective normalization.

1. Generate an architecture.
2. Calculate area, power, and dollar cost.
3. Simulate the workload sequence.
4. Calculate operational carbon with `total_opC()`.
5. Calculate embodied carbon with `find_carbon()` in `chiplet/carbon_model/ECO_chip.py`.
6. Store min, max, mean, median, standard deviation, and average values.
7. Write a workload calibration JSON and CSV.

`main.calibration_identity()` binds calibration to the model version, search
space, workload sequence, and intermediate-memory policy. Stale calibration is
regenerated by the current implementation.

Network calibration is handled by the corresponding helpers in `network.py`
and is stored under `cfg/calibration/networks/`.

## Simulation And Cache Flow

`main.simulate_latency_energy()` prepares and evaluates each GEMM in sequence.
For each GEMM:

1. `build_scheduler_system()` creates a scheduler and chiplet system.
2. `Scheduler.static_workload_scheduling()` partitions tiles across cores.
3. `SimulationCache.all_cores_simulation_with_cache()` looks up SCALE-Sim results.
4. `system/utils/Simulator.py` generates SCALE-Sim inputs and runs SCALE-Sim on a cache miss.
5. Scheduler modeling combines compute, DRAM, SRAM, and chiplet communication costs.

`system/utils/SimulationCache.py` owns the CSV cache. Its cache key includes
the model version, core shape, dataflow, bandwidth, SRAM size, and GEMM shape.
`SIMULATION_MODEL_VERSION` prevents incompatible historical rows from being
reused.

## Intermediate-Memory Flow

`system/utils/IntermediateMemoryPolicy.py` handles each boundary between
adjacent GEMMs.

Supported policies:

- `cold_dram`: spill and reload through DRAM.
- `ideal_on_chip`: remove the internal transfer as an upper bound.
- `local_sram`: retain a boundary only when placement and capacity allow it.
- `direct_forward`: retain same-core slices and route remote slices through existing links.

`build_boundary_mapping()` derives producer/consumer tile transfers.
`plan_boundary()` selects a policy result or falls back to cold DRAM with a
recorded reason. `main.simulate_latency_energy()` adds boundary latency and
communication energy to the ordered sequence totals.

## Objective Flow

`main.calculate_cost()` combines:

- Latency and communication energy from sequence simulation.
- SRAM energy from the scheduler.
- Compute energy from system power and latency.
- Area, power, and dollar cost from `chiplet/n_utils.py`.
- Embodied carbon from `chiplet/carbon_model/ECO_chip.py`.
- Operational carbon from `chiplet/n_utils.py`.
- Calibration-based normalization and profile weights from `cfg/parameters/cost_profiles.json`.

The result is a scalar objective plus normalized and raw metric dictionaries.

## Simulated-Annealing Flow

`main.sim_annealing()` performs the search:

1. Load or regenerate calibration.
2. Generate or clone the initial architecture.
3. Evaluate the initial objective.
4. Mutate either workload mapping or architecture.
5. Evaluate the candidate through the full objective flow.
6. Compare candidate cost with the current accepted state.
7. Accept improvements or probabilistically accept regressions through `accept_move_func()`.
8. Track the accepted current state separately from the global best.
9. Record metrics and architecture details.
10. Cool the temperature and repeat until freezing.
11. Return the best architecture and traces.

The current CLI call in `main.py` uses the short production settings:

```text
initial_temp=40
freezing_temp=1e-3
max_move_per_temp_step=5
cooling_rate=0.3
```

The callable `sim_annealing()` defaults and the README's documented defaults
are different. The README schedule used in the recent convergence experiments
was:

```text
initial_temp=4000
freezing_temp=1e-3
max_move_per_temp_step=50
cooling_rate=0.99
```

## Fixed-Architecture Evaluation Flow

Policy and network benchmark paths do not run simulated annealing.

```text
fixed architecture JSON
    |
    v
network.evaluate_network()
or main.run_policy_comparison()
    |
    v
simulate_latency_energy()
    |
    v
latency, energy, area, cost, policy and boundary reports
```

These paths evaluate a supplied architecture. SCALE-Sim may still run on cache
misses, but no architecture mutations or SA acceptance decisions occur.

## Tests

Tests are under `tests/` and run through unittest discovery. The main groups are:

- `test_workload_sequences.py`: ordered GEMM parsing and sequence accounting.
- `test_network_workloads.py`: network schema and compilation.
- `test_network_evaluation.py`: fixed-architecture network evaluation.
- `test_intermediate_memory_policies.py`: boundary planning and fallback behavior.
- `test_intermediate_capacity_validation.py`: live capacity and policy validation.
- `test_simulation_cache.py`: cache keys, model versions, and scheduler accounting.
- `test_architecture_identity.py`: architecture fingerprints.
- `test_optimizer_experiments.py`: experiment helpers and schedule budgets.

## Current Caveats

- `main.py` performs configuration loading at import time.
- `fast_test=True` is analytical and is not cycle-accurate SCALE-Sim execution.
- The README, callable SA defaults, and CLI SA settings are not currently unified.
- `run_policy_comparison()` validates calibration identity against the default policy while evaluating multiple policies; this should be treated as a known review item until policy-specific calibration handling is resolved.
- Some mutation paths report invalid proposals as skipped moves; experiment diagnostics count these separately.
- The D2D protocol-shadowing issue in `chiplet/n_utils.py` was intentionally not fixed during the convergence experiments.
- Generated reports, caches, `__pycache__`, calibration files, and architecture outputs are working artifacts, not source-of-truth implementation files.
